1. PREREQUISITES
================================================================================

You will need:
  - A Twitch account (your broadcaster account)
  - Optionally a second Twitch account for the bot to post as
  - A Cloudflare account (free tier works)
  - Node.js installed locally (for the one-time KV seed script)
  - The Wrangler CLI: npm install -g wrangler

Log into Wrangler:
  wrangler login


================================================================================
2. TWITCH DEVELOPER CONSOLE
================================================================================

Go to: https://dev.twitch.tv/console/apps

A) If you already have a Twitch Application, open it. Otherwise click
   "Register Your Application" and create one.

   Name:          PhantomACE (or whatever you want)
   Category:      Chat Bot

B) Note these two values — you'll need them later:
   - Client ID       (shown on the app page)
   - Client Secret   (click "New Secret" to generate one — SAVE IT, you
                      can't see it again)

C) Under "OAuth Redirect URLs", add BOTH of these:

   https://YOUR-DOMAIN.com/api/auth/twitch
   https://YOUR-DOMAIN.com/api/admin/bot-setup

   Replace YOUR-DOMAIN.com with your actual Cloudflare Pages domain
   (e.g., phantomace.pages.dev or your custom domain).

   Click "Save".

D) Find your Twitch User ID (Broadcaster ID):
   Go to: https://www.streamweasels.com/tools/convert-twitch-username-to-user-id/
   Enter your Twitch username and note the numeric User ID.


================================================================================
3. CLOUDFLARE KV NAMESPACE
================================================================================

In your terminal, run:

  cd "PhantomACE Website"
  npx wrangler kv:namespace create MARKETPLACE

This outputs something like:
  { binding = "MARKETPLACE", id = "abc123..." }

Copy that "id" value.

Now run:
  npx wrangler kv:namespace create MARKETPLACE --preview

Copy that "id" too (this is the preview_id).

Open wrangler.toml and replace the placeholder IDs:

  [[kv_namespaces]]
  binding = "MARKETPLACE"
  id = "THE-PRODUCTION-ID-YOU-JUST-GOT"
  preview_id = "THE-PREVIEW-ID-YOU-JUST-GOT"


================================================================================
4. CLOUDFLARE R2 BUCKET
================================================================================

This is for the media gallery upload feature.

Run:
  npx wrangler r2 bucket create phantomace-media

That's it. The wrangler.toml already has the binding configured:

  [[r2_buckets]]
  binding = "MEDIA_BUCKET"
  bucket_name = "phantomace-media"


================================================================================
5. CLOUDFLARE ENVIRONMENT VARIABLES
================================================================================

Go to: https://dash.cloudflare.com
Navigate to: Workers & Pages > your project > Settings > Environment variables

Add each of these as ENCRYPTED secrets for the Production environment:

  TWITCH_CLIENT_ID          Your Twitch app Client ID from Step 2B
  TWITCH_CLIENT_SECRET      Your Twitch app Client Secret from Step 2B
  TWITCH_BROADCASTER_ID     Your numeric Twitch User ID from Step 2D
  TWITCH_EVENTSUB_SECRET    A random string for webhook verification
                            (generate one: open a terminal and run
                            node -e "console.log(require('crypto').randomBytes(24).toString('hex'))"
                            or use the one generated on the bot setup page later)

Optional (the bot setup page stores these in KV automatically, but you
can also set them as env vars if you prefer):

  TWITCH_BOT_REFRESH_TOKEN  OAuth refresh token for the bot (from Step 7)
  TWITCH_BOT_USER_ID        The bot account's Twitch user ID

Also create a .dev.vars file in the project root for local development:

  TWITCH_CLIENT_ID=your-client-id-here
  TWITCH_CLIENT_SECRET=your-client-secret-here
  TWITCH_BROADCASTER_ID=your-user-id-here
  TWITCH_EVENTSUB_SECRET=your-random-secret-here

This file is already gitignored.


================================================================================
6. DEPLOY TO CLOUDFLARE PAGES
================================================================================

Option A — Git integration (recommended):
  1. Push the repo to GitHub
  2. In Cloudflare dashboard: Workers & Pages > Create > Pages > Connect to Git
  3. Select the repo
  4. Build settings:
     - Framework: None
     - Build command: (leave empty)
     - Output directory: /  (the project root)
  5. Deploy

Option B — Direct upload:
  npx wrangler pages deploy . --project-name phantomace-website

After deploying, your site is live at:
  https://phantomace-website.pages.dev (or your custom domain)


================================================================================
7. BOT AUTHORIZATION (CHAT MESSAGES)
================================================================================

This step authorizes the bot to send messages in your Twitch chat.
Everything is handled through a web page — no code or terminal needed.

A) Log in to your website as the broadcaster.
   (Go to your site and click Log In with Twitch)

B) Visit: https://YOUR-DOMAIN.com/api/admin/bot-setup

C) You'll see the setup dashboard with three steps.

D) Click "Authorize with Twitch" under Step 1.

E) Twitch will ask you to log in. Log in with whichever account you want
   the bot to post as:
   - Your main broadcaster account (messages appear as you), OR
   - A separate bot account (messages appear as the bot — recommended)

   If using a separate bot account, make sure that account is a moderator
   in your channel so it can post without rate limits.

F) After authorizing, you'll see a success page. The OAuth tokens are
   stored in KV automatically — no env vars needed for this part.

G) The bot can now send chat messages. The refresh token auto-renews,
   so this is a one-time step unless you revoke access.


================================================================================
8. EVENTSUB WEBHOOKS (HYPE TRAIN + CHANNEL POINTS)
================================================================================

This registers Twitch to send webhook events to your Cloudflare functions.

A) On the same bot setup page (https://YOUR-DOMAIN.com/api/admin/bot-setup),
   scroll to Step 2.

B) Click "Create Subscriptions".

C) This creates 4 EventSub subscriptions:
   - channel.hype_train.begin      → /api/hype-train
   - channel.hype_train.progress   → /api/hype-train
   - channel.hype_train.end        → /api/hype-train
   - channel.channel_points_custom_reward_redemption.add → /api/channel-points

D) You should see green checkmarks for each. If any fail, the error
   message will tell you what's wrong (usually a missing env var).

E) Twitch verifies each webhook URL by sending a challenge request.
   Your Cloudflare functions handle this automatically.

That's it! Twitch will now send events to your site whenever:
  - A hype train starts, progresses, or ends
  - Someone redeems a channel point reward


================================================================================
9. SEED GIVEAWAY CODES INTO KV
================================================================================

The hype train bot drops giveaway codes in chat. These codes are pre-generated
and stored in KV. Run this once to seed them:

  cd "PhantomACE Website"
  node _private/seed-giveaway-codes.js

This uploads the codes from _private/giveaway-codes/ into KV:
  - gc_common     — 50,000 codes (2 bonus entries each)
  - gc_uncommon   — 30,000 codes (5 bonus entries each)
  - gc_rare       — 20,000 codes (15 bonus entries each)
  - gc_mythic     — 10,000 codes (50 bonus entries each)

The codes are 7-character alphanumeric strings with zero overlap between tiers.


================================================================================
10. VERIFY EVERYTHING WORKS
================================================================================

A) Check the bot setup page shows green checkmarks for both steps.

B) Test chat posting (optional):
   You can test by manually calling the chat API from your browser console
   while on the site:

   fetch('/api/channel-points?action=poll', {credentials:'same-origin'})
     .then(r => r.json()).then(console.log)

   This should return { redemptions: [] } if you're logged in.

C) Hype train testing:
   Twitch doesn't have a test mode for hype trains, but you can verify
   the webhook is registered by checking the Twitch CLI:

   twitch api get eventsub/subscriptions

   Or in the EventSub section of the Twitch Developer Console.

D) Channel point testing:
   Create a test channel point reward on your Twitch channel and redeem it.
   If it matches one of the mapped reward names (containing "skull" + "boost",
   "theme", "wheel"/"spin", or "shoutout"), it will be processed.

E) Site banner:
   During an active hype train, every page on the site will show a glowing
   orange progress bar below the header.

11. HOW IT ALL WORKS (REFERENCE)
================================================================================

ARCHITECTURE:
  - All code runs as Cloudflare Pages Functions (serverless)
  - No always-running server or bot process
  - Twitch sends HTTP webhooks → Cloudflare function runs → responds
  - State stored in Cloudflare KV (key-value store)
  - Media files stored in Cloudflare R2 (object storage)

HYPE TRAIN FLOW:
  1. Hype train starts on Twitch
  2. Twitch sends webhook to /api/hype-train
  3. Function stores state in KV, posts announcement in chat
  4. At levels 2/3/4/5, function pulls a giveaway code from KV
  5. Function posts the code in Twitch chat via Helix API
  6. Site polls /api/hype-train?action=status every 15 seconds
  7. When active, a progress bar banner appears on every page
  8. When hype train ends, function posts summary and clears state

HYPE TRAIN CODE DROP LEVELS:
  Level 5  → 4 Common codes   (2 bonus giveaway entries each)
  Level 10 → 3 Uncommon codes (5 bonus giveaway entries each)
  Level 15 → 2 Rare codes     (15 bonus giveaway entries each)
  Level 20 → 1 Mythic code    (50 bonus giveaway entries)

  All codes expire after 5 minutes. They appear:
  - In Twitch chat (posted by the bot)
  - On the giveaway page (phantomace.com/giveaway) with countdown timers
  Expired codes are removed from both locations automatically.

CHANNEL POINT REWARDS:
  The system maps reward titles to actions by keyword:
  - "skull" + "boost"  → 2x multiplier in Skull Clicker for 5 minutes
  - "theme"            → Unlocks a site theme cosmetic
  - "wheel" or "spin"  → Queues a spin-the-wheel event
  - "shoutout"         → Queues a community shoutout

BOT TOKEN MANAGEMENT:
  - OAuth refresh token stored in KV (key: twitch_bot_refresh_token)
  - Access token auto-refreshes when expired (cached in KV)
  - No manual token rotation needed
  - If the bot stops working, re-authorize at /api/admin/bot-setup

API ENDPOINTS:
  /api/hype-train          POST: EventSub webhook receiver
                           GET:  ?action=status (site polling)

  /api/channel-points      POST: EventSub webhook receiver
                           GET:  ?action=poll (client redemption queue)
                           GET:  ?action=skull-boost (boost check)

  /api/admin/bot-setup     GET:  Setup dashboard (broadcaster only)
                           POST: Create EventSub subscriptions

  /api/bingo/*             Commander Bingo game state
  /api/mana-clash          Mana Clash multiplayer rooms
  /api/media/upload        Media gallery uploads (R2)
  /api/inventory           Shared inventory system
  /api/phamily-time        Watch time tracking + rewards
  /api/auth/twitch         Twitch OAuth login
  /api/auth/logout         Session logout
  /api/import-badges       Twitch sub badge import

KV KEYS USED:
  bingo_{CODE}             Bingo game state
  mc_room_{CODE}           Mana Clash room state
  inv_{userId}             Player inventory
  pt_{userId}_{month}      Phamily Time monthly data
  pt_alltime_{userId}      Phamily Time lifetime stats
  gc_{rarity}              Giveaway code pool (array)
  gc_ptr_{rarity}          Giveaway code pointer (next index)
  hype_train_active        Current hype train state + dropped levels
  hype_train_site          Hype train state for site banner
  cp_queue_{userId}        Channel point redemption queue
  cp_skull_boost_{userId}  Active skull boost data
  twitch_bot_token         Cached bot access token
  twitch_bot_refresh_token Bot refresh token
  twitch_bot_user_id       Bot Twitch user ID
  twitch_app_token         Cached app access token
  media_index              Media gallery metadata index
  eventsub_subscriptions   Registered EventSub subscription list

12. TROUBLESHOOTING
================================================================================

BOT NOT POSTING IN CHAT:
  - Visit /api/admin/bot-setup and check if the bot token is stored
  - Re-authorize if needed (click "Authorize with Twitch" again)
  - Make sure the bot account is a moderator in your channel
  - Check Cloudflare Pages function logs for errors

EVENTSUB WEBHOOKS NOT FIRING:
  - Check that subscriptions exist: visit /api/admin/bot-setup
  - Re-create subscriptions if needed
  - Make sure TWITCH_EVENTSUB_SECRET env var matches what was used
    when creating subscriptions
  - Twitch requires HTTPS — make sure your domain has SSL (Cloudflare
    Pages provides this automatically)

GIVEAWAY CODES RUNNING OUT:
  - Generate more codes and re-run the seed script
  - The pointer tracks which code is next, so new codes need to be
    appended to the existing arrays (or reset the pointer)

HYPE TRAIN BANNER NOT SHOWING:
  - The site polls every 15 seconds — may take a moment to appear
  - Check browser console for fetch errors
  - Verify /api/hype-train?action=status returns data

MEDIA UPLOADS FAILING:
  - Make sure the R2 bucket exists: npx wrangler r2 bucket create phantomace-media
  - Check that MEDIA_BUCKET binding is in wrangler.toml
  - Max file size is 10MB
  - Allowed types: JPEG, PNG, GIF, WebP, MP4, WebM
